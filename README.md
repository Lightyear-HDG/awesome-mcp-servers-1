## How to add your MCP server

These instructions are for adding your server to this repo.

### Clone the repository

```bash
git clone https://github.com/modelcontextprotocol/awesome-mcp-servers
cd awesome-mcp-servers
```

### Edit the README

Create a new branch for your server and update the README.md file with your server entry. Use the following format:

- **[Server Name](Server GitHub Link)** - Server description

The description should be:
- One line
- Concise
- Highlight what makes your server unique
- Include tools count if relevant

### Place your entry in the appropriate section

Find the correct section for your server:

#### Sections

1. **Hosted Servers** - Servers available as hosted services
2. **Local Servers** - Servers for local deployment
3. **Community Servers** - Community-built servers

#### Categories within sections

- **API & Data Services** - Web APIs, data platforms, search
- **Blockchain & Web3** - Crypto, blockchain, smart contracts
- **Business & Finance** - CRM, accounting, business tools
- **Developer Tools** - Git, Docker, cloud platforms, CI/CD
- **Content & Knowledge** - Documentation, wikis, note-taking
- **Science & Environment** - Research, environmental monitoring
- **Utilities & Fun** - Tools and games

### Keep entries alphabetically sorted

Entries within each category should be sorted alphabetically by server name.

### Commit and push your changes

```bash
git add README.md
git commit -m "Add [Server Name] MCP server"
git push origin your-branch-name
```

### Create a pull request

Note: The repository no longer accepts pull requests via GitHub. Please submit your MCP through the official website instead: https://mcpservers.org/submit

**Disclaimer**: This directory is maintained as a community resource. Please refer to individual server documentation for usage, security, and licensing information. Always review third-party server code before integrating into your environment.

**Note on Server Selection:** Before using any MCP server, especially those from community contributors, please:

1. Review the server's source code
2. Check the server's documentation and license
3. Understand the server's authentication and data handling practices
4. Test the server in a safe environment first
5. Monitor the server's behavior in production

This is especially important for servers that handle sensitive data or perform operations on your behalf.

**Note on Security:** MCP servers have access to your system and can perform actions on your behalf. Always use servers from trusted sources and review their code before deploying. For security-sensitive operations, consider running servers in isolated containers or VMs.

**Note on Maintenance:** Servers listed here may not be actively maintained. Please check the repository's last commit date and issue status before relying on a server for production use.

**Note on Containerization:** The MCP specification supports containerized deployment for improved security and isolation. Many production deployments use Docker, Kubernetes, or other container systems for centralized management of MCP servers, ensuring ease of use, consistency, and security through containerization
